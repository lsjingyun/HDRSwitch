macOS 菜单栏工具

HDRSwitch 使用说明

一个挂在菜单栏上的 HDR 开关。系统设置里没有这个开关的时候它替你打开； 播 HDR 片源时它自己打开，播完自己关掉，顺手把刷新率还给你。

版本 1.0.2 · 2026-10-30 · 需要 macOS 13 及以上；已在 macOS 26/27 + Apple Silicon 实测

01安装与第一次打开

DMG 打开后只有一件事要做：把 HDRSwitch 拖到旁边的 Applications 文件夹上。

然后第一次打开会被 macOS 拦一次——因为它没有做 Apple 公证（个人工具，签名是本地 ad-hoc 的）。

「无法验证开发者」怎么办：在「应用程序」里按住 Control 点 HDRSwitch → 选「打开」→ 弹窗里再点一次「打开」。只需要做一次，以后正常双击。

另一条路：系统设置 → 隐私与安全性 → 往下滚，会看到「已阻止使用 HDRSwitch」→ 点「仍要打开」。

打开后没有窗口、没有 Dock 图标，只有一个图标出现在屏幕右上角的菜单栏里。这是正常状态。

03自动切换：它凭什么判断

不是猜的，也不是看文件名（文件名只在最后兜底）。它按「能拿到多少信息」分三条路走，越往下越保守。

判定规则（偏保守：宁可漏判，也不误判成 HDR）

片源的色彩标记判定
传输曲线是 PQ（SMPTE ST 2084）或 HLGHDR
色域 BT.2020，且曲线也是 PQ / HLGHDR
色域 BT.2020，但曲线是 BT.709（宽色域 SDR 母版）SDR
完全没有色彩标记，且 8bit 或 1080p 及以下SDR（HDR 必然 10bit 起步，也没有 1080p 的 HDR 片源）
完全没有色彩标记，4K + 10bit未知 → 默认不切（可放开菜单里那条「识别不到片源时也开 HDR」）

所以像「WEB-DL 的 mkv 容器里根本没写色彩信息」这种情况，它会继续往下读码流的参数集，报出 HEVC · 3840×1608 · 10bit · PQ · BT.2020 这样的结论，而不是看文件名瞎猜。

时间线大致是什么样

时刻发生的事
打开片源1～2 秒内识别出 HDR
+3～4 秒自动开 HDR（必要时先换显示模式），画面黑一下
播放中每秒检查一次；暂停不关，因为播放器还占着「正在播放」
退出播放器进入宽限期（默认 30 秒），防止暂停、切集来回切
+30 秒关 HDR，刷新率切回原来的 144Hz

支持的播放器没有白名单限制——任何 App，只要它打开了媒体文件就能被认出来。白名单（IINA、Infuse、QuickTime、TV、VLC、Movist、Plex 等）只是额外保证「拿不到文件时」也能判断在不在播。

下载器不算播放器。qBittorrent、Transmission、迅雷、Motrix 这类工具会长时间持有 .mkv 的句柄——下载中、做种中——但它们从不播放。工具按 bundle id 和名称把它们整个排除，另有一层兜底：文件正在变大、或刚写完 4 秒以内，都不算播放。所以一边下 HDR 片源一边看别的，屏幕不会被切过去。

04网页视频（B 站 / YouTube）

网页里的视频，色彩信息不对外暴露。唯一的办法是让浏览器在当前标签页跑一小段 JavaScript，去问播放器「你现在是什么画质」。所以这条路需要两个系统授权，缺一条就静默失效。

先确认这两处

要什么怎么开
自动化权限 第一次探测时系统会弹窗问「HDRSwitch 想要控制 Safari」，点允许。没弹或点错了：系统设置 → 隐私与安全性 → 自动化 → 勾上 HDRSwitch 下面的 Safari
Safari 里的 JS 开关 Safari 设置 → 高级 → 勾「显示网页开发者功能」→ 切到新出现的「开发者」标签页 → 勾「允许 Apple 事件中的 JavaScript」

Safari 27 把那个 JS 开关挪位置了。它不在「开发」菜单里，在设置 → 开发者标签页。找菜单会白找半天。

Chrome / Edge / Arc 走的是另一套（AppleScript 执行 JS），只需要自动化授权，不用改浏览器设置。

B 站

读播放器当前的画质码：125 = HDR 真彩，126 = 杜比视界，其余按 SDR 处理。画质标签显示「自动」且读不到码时不切——它宁可不动，也不猜。

YouTube：先有鸡还是先有蛋

YouTube 有个死结：显示器不是 HDR 时，它压根不给你 HDR 选项。所以「等检测到 HDR 再切」这条路永远等不到。工具的解法是绕开播放器，直接看页面里的播放响应——片源有没有 HDR 版本，跟你的显示器状态无关。

查到有，就按顺序做三件事：

  1. 先切 HDR——让 HDR 选项出现；
  2. 重建一次播放器（约 1 秒，保留当前进度）——因为可用格式列表是播放器初始化时按当时能力建的，不重建它不会自己重算；
  3. 把画质拉到最高那一档——实测切完 HDR 后 YouTube 会自己在 1080p 待 85 秒不上去，所以直接拉过去。

画质档位是按屏幕封顶的。面板只有 5K 时，8K（4320p）片源会被封到 2160p——多出来的像素看不见，8K 解码和带宽却是实打实的，撑不住就会卡。

而且锁的是区间不是单档（比如 1440p~2160p）。万一 4K 分片取不到数据，播放器还能先降到 1440p 继续播，而不是卡死等数据。另外页面里有个看门狗，卡住 10 秒会松绑、20 秒会轻推一下、40 秒放弃这次高画质尝试。

探针读的是你眼前这一页（当前标签页）。Safari 里同时开着几个视频标签时，判定的是正在看的那个，不是旁边还在响的那个。

05Infuse 播共享里的片源

Infuse 播本机共享（「王进的 Mac mini (SMB)」这种）里的文件时，它自己进程里一个文件句柄都没有——数据是 SMB 协议流进来的。真正打开文件的是系统那头的 smbd，而它跑在 root 下，普通用户看不到它在读什么。

所以要装一个只读的小工具。它唯一的功能就是：列出 smbd 当前打开的视频文件。拿到文件名之后，判定和本地文件完全一样。

怎么装

  1. DMG 里进 可选组件（共享识别） 文件夹；
  2. 双击 安装共享识别.command；
  3. 输入一次管理员密码。

它会做两件事：装 /usr/local/libexec/hdrswitch-smbdump，并在 /etc/sudoers.d/hdrswitch 里只放行这一条命令（不接受任何参数），之后 App 免密调用它。装完回到菜单，「共享片源识别」应该显示为已就绪。

不想装也能用，只是这一类片源会退化成「只知道在播」：默认不切 HDR。另一条替代路是给 HDRSwitch 开「完全磁盘访问权限」，也能读到 smbd 的句柄。

另外，如果 Infuse 播的是别的机器上的 NAS / Plex，那就跟这里无关——那种情况本来就拿不到画质。

06为什么会掉到 60Hz、黑屏多久

这不是偷懒，是 HDMI 带宽决定的。以这台 LG ULTRAGEAR+（5120×2880，HDMI 连接）实测：

显示模式系统认为支持 HDR
2560×1440 Retina @144Hz❌ 不支持
2560×1440 Retina @120Hz❌ 不支持
2560×1440 Retina @60Hz✅ 支持

144Hz 已经把链路吃满，没有余量留给 HDR 要的 10bit 和元数据，于是 macOS 干脆把 HDR 开关藏起来——这就是「系统设置里找不到 HDR」的真正原因。

所以它的做法是：开 HDR 就切到 60Hz；关 HDR 就切回你原来的 144Hz。如果你的显示器在原生模式下就支持 HDR（Studio Display、Pro Display XDR、带宽充裕的 4K 屏），它不会碰分辨率，只做纯粹的开关。

黑屏时间

这里其实有两次黑屏：一次换显示模式（硬件重新握手），一次系统真正切 HDR 标志。现在把它们压成了一次：

开：656ms  （原来 1650ms、黑两次）
关：669ms  （原来 1705ms）

剩下的 ~620ms 全在面板重新握手上，属于硬件下限。

想再快只能不切模式，那样在这块屏上就开不了 HDR。

全屏播放时窗口可能跳到另一个桌面——这是 macOS 换模式时的行为，软件管不了。想避免就在窗口模式下播。

07命令行

适合接快捷指令、自动化、或者排查问题时用。B=/Applications/HDRSwitch.app/Contents/MacOS/HDRSwitch：

命令做什么
$B status当前显示器、模式、是否支持 / 是否已开 HDR
$B on / off / toggle开关、反转
$B list列出所有显示器
$B modes列出型号支持的所有显示模式（排查带宽用）
$B detect 文件判断某个片源是不是 HDR，会说明依据
$B sessions当前检测到的播放会话（谁在播、判成什么）
$B smb共享片源识别的状态与细节
$B web网页探测的开关状态、最近一次判了什么
$B why最有用的一条：一次列出显示器状态、现场识别结果、是否被手动接管、失败计数、最近日志
$B auto前台跑监视器，实时看每轮判定
$B menu把菜单结构打印出来（含勾选状态）

命令行里跑 sessions / why 时，网页探测一定失败。不是坏了：系统按「谁发起的」判授权，终端进程没有这个权限，只有菜单栏那个 App 进程有。

想看 App 刚刚判了什么：defaults read com.wangjin.hdrswitch autoLastSession，里面带着完整依据。

08出问题了怎么查

按这个顺序，基本三步内能定位：

  1. 菜单 → 复制诊断信息，粘出来看一眼。里面是显示器状态 + 当前识别结果。
  2. $B why。它会直接告诉你「为什么没切」：没检测到播放？判成了 SDR？还是被你手动接管了？
  3. 看日志。路径 ~/Library/Logs/HDRSwitch.log，超过 512KB 自动清空，不会吃硬盘。

日志里值得看的几行

行首怎么读
详情:判定依据。写着片源分辨率、色彩、画质、视频 id。比如 3840×2160 · smpte2084 · quality hd2160
健康:网页播放有没有卡住。卡住时是 adv=0 buf=0（画面不前进、缓冲为 0）
切换耗时这次开关用了多少毫秒，分段写着时间花在哪
actuate真正动手切了（开或关）

前三行默认就写，不需要开调试。要每轮判定都记（会刷屏，排查完记得关）：

defaults write com.wangjin.hdrswitch debugLog -bool true
# 重启 App 生效
defaults write com.wangjin.hdrswitch debugLog -bool false

09常见问题

系统设置里根本找不到 HDR 开关？

因为你现在的刷新率把带宽吃满了。切到 60Hz 再看就有了——这也是这个工具存在的理由。见第 06 节。

播 HDR 片源没切？

依次排三件事：

  • 「播放 HDR 内容时自动开启」是不是被关掉了；
  • 片源来自 NAS / 网络串流？那种情况拿不到画质，默认不切；
  • 你刚才是不是手动点过开关——手动接管期间自动逻辑不插手。

命令行的 why 会直接说出是哪一条。

播 SDR 反而切了？

检查这两条有没有被打开：「网页视频一律按 HDR 切」「播放器识别不到片源时也开 HDR」。这两条都是「读不到画质就硬切」，开着就一定会误切 SDR。

挂着 qBittorrent 下片，HDR 自己开了？

下载器会长时间攥着 .mkv 的句柄（下载中、做种中），以前会被误当成「在播 HDR」。现在的构建里下载器整个不参与判定，认不出的客户端还有「文件正在变大就不算播放」这条兜底。确认方法：$B why 里会多出一行「已忽略下载器」，列出被拦下的进程。

网页视频一点反应都没有？

九成是那两个授权之一没就位（自动化 / Safari 的 JS 开关）。跑 $B web，它会直说卡在哪一步。

YouTube 切了 HDR，画质却停在 1080p？

看「解锁后直接选 4K HDR 画质」有没有开。另外 8K 片源会被封到 2160p，这是有意的——不是没拉到顶。

切完 HDR 之后断流 / 卡住不动？

这是画质锁导致的取不到数据，不是网速也不是解码问题。现在有看门狗会自动松绑，通常十几秒内自己恢复。如果反复出现，把那个视频链接发我，日志里 健康: 那行能看出是哪一步。

暂停了，HDR 一直开着不关？

这是设计。判断依据是「播放器还在占着正在播放」，不是「画面在动」。退出播放器才会走宽限期、然后关掉。

重启 App 后 HDR 一直开着？

如果 App 是在播放中途被重启的，它会续上宽限期，避免「明明没在播却一直停在 HDR」。手动切一次就恢复正常。

HDR 模式下我自己改了分辨率，状态不对了？

切一次 HDR（开→关，或关→开）就会重新同步。

10卸载 · 已知限制

卸载

先从菜单退出，然后：

rm -rf /Applications/HDRSwitch.app
defaults delete com.wangjin.hdrswitch

# 装过共享识别小工具的话，一并清掉
sudo rm -f /usr/local/libexec/hdrswitch-smbdump /etc/sudoers.d/hdrswitch

如果开了「开机自动启动」，退出前先在菜单里关掉它。

已知限制

  • 只在 Apple Silicon + macOS 26/27 上验证过。用的是系统私有接口，大版本升级后可能失效——重编一次通常就好。
  • 部分显示器（尤其经过转接器 / 扩展坞连接的）压根不回报 HDR 能力，那种情况没有任何软件能打开。
  • Infuse 播远程 NAS / 媒体服务器：拿不到画质，默认不切。要切只能打开「播放器识别不到片源时也开 HDR」，代价是 SDR 片源也会被切。
  • 网页探测依赖页面结构。B 站改版、YouTube 换播放器实现，都可能让画质读不到——读不到就不切，不会误切。
  • 切换必然黑一下（约 0.7 秒）并伴随一次显示模式变更，这是 macOS 的行为。

11版本记录

1.0.2 · 2026-10-30

  • 图标现在会出现在 Launchpad 里。之前 Info.plist 里标了 LSUIElement（「菜单栏专用 App」），macOS 会因此把 App 从 Launchpad 的图标列表和「应用程序」页里一并排除——只有 Spotlight 搜得到，翻是翻不到的。现在这个标记去掉了，改成启动后用 setActivationPolicy(.accessory) 收掉 Dock 图标：行为完全一样（没有 Dock 图标、不进 ⌘Tab、不抢焦点），但 Launchpad 和「应用程序」里能正常看到、正常点开。
  • 编译产物从项目根目录挪到 build/。项目里的 .app 会被 Spotlight 收进 Launchpad，编译几次就会看到好几个重复图标——这也是「Launchpad 里出现 3 个 HDRSwitch」的原因。

1.0.1 · 2026-10-30

  • 修掉「下载器被当成播放器」：qBittorrent 下 HDR 片源时，屏幕会被误切到 HDR。下载器会长时间持有 .mkv 句柄（下载中、做种中）却从不播放，现在它们整个不参与判定（含 Transmission、迅雷、Motrix、Folx、Downie、FDM、网盘客户端等），另加「文件正在变大、或刚写完 4 秒以内不算播放」的兜底。$B why 会多打一行「已忽略下载器」。
  • 本机 SMB 那条线同样过滤正在写入的文件——往共享目录里拷片源不会再触发切换。
